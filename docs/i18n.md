# Interface languages

The interface (buttons, menus, settings, tooltips, the built-in tutorial, generated tours) speaks
English and Japanese. This is separate from the **codecast language** (`State::lang`, the
language a codecast plays and is translated into, `crates/iwr-core/src/i18n.rs`): a Japanese
viewer can follow an English codecast with Japanese buttons, and the other way round.

## Where the texts are

| Texts | Files | Called as |
|-------|-------|-----------|
| Web UI | `crates/iwr-ui/i18n/<lang>/<module>.toml` | `t::settings::title()` (current language) |
| Core: view names, empty-view notes, item details, the built-in tour, generated tours | `crates/iwr-core/i18n/<lang>/<module>.toml` | `t::views::label_code(lang)` (language passed in) |
| Built-in tutorial | `crates/iwr-ui/assets/tutorial/` (English), `crates/iwr-ui/assets/tutorial/ja/` | picked by the interface language |

`en` is the reference language. Each language directory has a `_lang.toml` with its own name
(`name = "日本語"`). One TOML file per Rust module that shows the texts (`settings.toml` for
`settings.rs`); the file name becomes the module of the generated functions.

The build (`crates/iwr-i18n-gen`) turns every key into a typed function and **fails** when:

- a key is missing in a language, or exists only there;
- the `{arguments}` differ between languages;
- a plural lacks a form its language needs (`one` + `other` in English, `other` in Japanese);
- a brace is malformed (a literal brace is `{{` / `}}`).

A call with the wrong arguments does not compile either.

```toml
# en/player.toml                          # ja/player.toml
play = "Play"                             play = "再生"
part_of = "Part {i} of {n}"               part_of = "パート {i} / {n}"
cues = { one = "{n} cue", other = "{n} cues" }
                                          cues = "{n} キュー"
[menu]                                    [menu]
open = "Open"        # → t::player::menu_open()   open = "開く"
```

A text without arguments returns `&'static str`; with arguments or a plural it returns `String`.
A plural always takes `n: usize` first.

## How the language is chosen

1. `?ui=ja` in the URL (not saved: for links, screenshots, `codecast video`);
2. the viewer's choice, saved in this browser (`localStorage` key `iwr-ui-lang`);
3. the browser's languages (`navigator.languages`), first one translated;
4. English.

The picker is in the top bar and at the top of Settings → Appearance. Switching redraws at once:
the generated functions read a global signal, so every component that shows a text subscribes
to it. `<html lang>` follows, so browsers pick Japanese glyph shapes and screen readers the
right voice. Every font stack ends with Japanese system fonts (Hiragino Sans, Yu Gothic UI,
Meiryo, Noto Sans CJK JP) before the generic family.

## Writing texts

- Never put an English sentence in a `rsx!`, a `title:`, a `data-tip:` or a status message:
  add a key. Code, file names, key names (`Esc`, `space`) and product names (Kokoro,
  IwannatRust) are not translated.
- Keep a sentence whole in one key with `{arguments}`; never glue translated pieces together
  (word order differs: `"{n} of {total}"` vs `"{total} 中 {n}"`).
- Texts kept in a signal (status lines) are translated when they are made; they show in the
  language of that moment.
- Group keys by place: `[menu]`, `[tip]`, `[desc]` tables.

## Japanese style

- Sentences (descriptions, tooltips, notes) in です・ます, ending with `。`.
- Buttons and labels: short noun or verb stem, no final `。` (`保存`, `開く`, `再生`, `設定`).
- Full-width punctuation in Japanese text: `、` `。` `（）` `「」` `：`. ASCII inside code.
- A half-width space between Japanese and Latin words or inline code: `Rust の struct`,
  `` `@ diagram` を使います``.
- Numbers stay half-width.
- Rust terms stay as written: `struct`, `enum`, `trait`, `impl`, `crate`, `fn`, `mod`, `//!`,
  `///`, `Result`, `Option`, `panic`, `?`.

## Text core tells in a language

The built-in tour and the generated tours are sentences core builds (`guide.rs`, `tours.rs`), so
they are told natively in each language of `crates/iwr-core/i18n/`. Inside them, the author's own
text (a doc comment, a `//` note, a TODO) stays as written, wrapped in `⟦…⟧` (`tr::authored`),
and the cue is marked `told`. The translation (`i18n::texts` / `apply`, the server's model, an
export's `translations/<lang>.json`) then only gets those pieces, and drops the marks. Without a
translation, `i18n::unmark` plays the author text as written. `script::Source::tell(project, lang)`
gives a codecast as told in a language; the player, the subtitles and `codecast translate` start
from it.

Typography that differs by language is code in `crates/iwr-core/src/tr.rs` (`gap` between
sentences, `led` after a lead word), matched exhaustively so a new language must decide.

## Checks

- The build checks the TOML files (above).
- `cargo test -p iwr-i18n-gen` also fails on English prose left in a string literal of
  `crates/iwr-ui/src/`. A literal that is not interface text on purpose says why on its line:
  `// i18n: sample drawn in Latin-only fonts`.
- `cargo test -p iwr-core` tells every tour and the built-in tour in Japanese and fails on an
  English template sentence left outside author text, and checks that the Japanese tutorial has
  the same parts, cues and screen moves as the English one.
- `cargo test -p iwr` fails when a tutorial's text changed since its recording.

## Adding a language

1. Copy `crates/iwr-ui/i18n/en/` and `crates/iwr-core/i18n/en/` to `<code>/`, set `_lang.toml`'s
   `name`, translate every value. The build lists whatever is missing.
2. If the build says it knows no plural rule for the code, add one in
   `crates/iwr-i18n-gen/src/lib.rs` (`plural_rule`).
3. Fill the exhaustive matches the compiler then points at (`tr::gap`, `tr::led`, the tutorial
   choice in `crates/iwr-ui/src/tutorial.rs`).
4. Write the tutorial in `crates/iwr-ui/assets/tutorial/<code>/` (same directive lines as the
   English one, only the words change) and record it:
   `codecast voice crates/iwr-ui/assets/tutorial/<code> --lang <code> --voice <kokoro voice> --written --path crates/iwr-core/tests/fixtures/demo`.
5. Add the glossary column here.
